# GTA giveaway leaderboard
This is distinct from Zs, the existing random giveaway system, and Kick's rolling Active Chatter List.
Each live stream has 30-minute blocks anchored to Kick’s start timestamp. A private seed stored per stream chooses one check-in during the final ten minutes of each block. One normal chat message between the previous check-in and the next earns 1 XP when that check-in is verified. An exact-boundary message qualifies for the next check-in. A stream that ends before its next check-in does not award an extra point for that partial interval. Commands, the host, known bots, and anonymous chat do not count. Check-ins from earlier streams persist.

After Kick confirms a stream ended, the owner selects it and enters the three Kick handles in order. The leaderboard adds 3, 2 and 1 XP in one transaction and rejects re-awarding a broadcast. The same submission can be retried safely. It accepts only three distinct accounts matched to eligible chat from that broadcast, so a typo cannot create a participant. Record bonuses before freezing. Tied scores display tied ranks; use the published contest rules, not alphabetical display order, to resolve a tied winner.

The database stores account ID, handle, time and interval, not chat content. Public standings expose handles, scores and ranks but no future check-in times. Healthy official channel observations advance verified time. Known feed gaps skip impacted check-ins without taking back previously completed check-ins. The owner freezes scoring and can mark a participant who passed. Prize delivery is manual. Nothing changes Zs.
## Release gate and smoke test
1. Apply the migration in staging. Test signed chat + live start/end and confirm the existing trivia/webhook path is unaffected. Verify the scheduler runs normally with consecutive healthy observations at most 150 seconds apart.
2. Set `GTA_GIVEAWAY_ENABLED=1` only in the target environment after migration and only with an approved public launch. It is off by default. The independent `GTA_GIVEAWAY_START_ALLOWED=1` enables the owner’s Start button only after release checks. The signed lifecycle subscription is checked and registered without removing the existing chat or reward subscriptions.
3. Publish the eligibility, tie-break, no-purchase rule, and prize details before starting a real campaign. The signed-in owner alone can start/stop/mark passed at `/#/gta-giveaway`. Check the published page from an unauthenticated browser.
4. Use a staging or announced test stream to confirm: repeated messages give one point; a boundary message belongs to the next window; offline messages give no points; another stream carries standings forward; exact-repeat top-three bonus entry does not double-award; failed validation does not apply partial bonuses. Stop only after the final included checkpoint. End the campaign manually after production acceptance. Do not advertise it until the live data path has been verified.
5. Turn off the feature flag to stop collection without deleting standings. On recovery, suspected missing blocks must not be reconstructed from viewer counts. A plain cron snapshot of a chatter list is not a substitute.
